# Next Changelog for CoCart React Native SDK <!-- omit in toc -->

> [!WARNING]
> This changelog is **NOT** final. It lists the changes waiting for the first release of `@cocartheadless/react-native-sdk`, to be moved into `CHANGELOG.md` under 1.0.0 when it's released. It needs `@cocartheadless/sdk` 1.3.0, which adds the methods and types below.

## Added

- **The hooks wait for the stored cart key.** `CoCartProvider` starts reading it as the client is created, and `useCart` and `useCartMutations` wait for that before their requests, so a returning guest gets their own cart rather than a new one (a screen's effects run before the provider's). `useCoCartContext()` returns the client with `sessionRestored`, to await before calling the client yourself as a screen mounts. A storage error no longer goes unhandled: the client starts a new cart.
- `useCartMutations()` returns `removeAllItems()` (keeps coupons and fees), `changePlan()` (switches a cart item to another subscription plan, or to one-time with `'0'`), `applyCoupon()` (with an optional email), `removeCoupon()` and `removeCoupons()`. `addItem()` takes a SKU or a numeric string, and its options are typed as `AddItemOptions` (a subscription plan, a gift recipient, a warranty).
- `useCart({ mini: true })` fetches the lighter mini cart (CoCart Plus).
- `useAccount()` returns the CoCart Plus 2.0 account methods: `register()`, `updateAddress()`, `cancelOrder()`, `verifyEmail()`, `sendOrderEmailVerification()`, `verifyOrderEmail()`, the subscription methods (`getSubscriptions()`, `getSubscription()`, `suspendSubscription()`, `reactivateSubscription()`, `cancelSubscription()`, `setSubscriptionAutoRenew()`, `updateSubscriptionPaymentMethod()`, `resubscribe()`, `cancelResubscribe()`) and `requestOrderWithdrawal()`. `changePassword()` sends only the passwords, `getOrderDownloads()` uses the order's own downloads route, and `getReviews()` takes query parameters.
- **Checkout (CoCart Plus 2.0).** With `@cocartheadless/checkout` installed and `createCheckout()` in `CoCartProvider`'s new `extensions` prop: `useCheckout()` (the checkout state, updated when a change is saved), `usePaymentMethods()` (the payment methods and the customer's saved cards, one request), `useCheckoutMutations()` (`update()`, `placeOrder()`, `payForOrder()`, `confirmReturn()`), `useOrderReceived()` for the thank-you screen, and `useCheckoutClient()` for the other checkout calls. `placeOrder()`, `payForOrder()` and `confirmReturn()` return a `CheckoutResult` read from the order CoCart Plus 2.0 returns (`code`, `isComplete`, `isAwaitingPayment` for Cash App Pay, WeChat Pay, Stripe vouchers and BLIK, `needsConfirmation` for 3D Secure, `needsRedirect`, `isPending`, `isFailed`, the order's ID, key and status), so a declined card is a result to read, not a thrown error. `usePaymentMethods()` gives the methods as a list and each saved card's `label`. `@cocartheadless/checkout` is an optional peer dependency. See `docs/checkout.md`.
- **Checkout: finding out how an order ended when no answer came back.** `useCheckoutMutations()` has `getCheckoutStatus(checkoutId)`: when `placeOrder()` throws `CheckoutOutcomeUnknownError` (from `@cocartheadless/checkout`) because no answer came back or another request was still taking payment for the cart, it asks CoCart Plus 2.0 how the checkout ended: `order_placed`, `payment_required`, `in_progress` or `not_placed`. The `CheckoutStatus` type is exported.
- `useAccount().updateSubscriptionPaymentMethod()` takes a new card in `payment_data` as well as a saved card's `token_id`, and returns a `CheckoutResult`, since a new card may need 3D Secure.
- Re-exports the core SDK's new types: the cart (`AddItemOptions`, `CartShipping`, `CartBillingAddress`, `CartShippingAddress`, `CartTotalsBreakdown`, `CartTax`, `RateLimitInfo`…), products (`ProductVariation`, `ProductOrderBy`, `SortOrder`, `StockStatus`, `ProductShippingRatesParams`, `ProductReviewInput`…), the account inputs (`RegisterCustomerInput`, `AccountAddressUpdateInput`, `OrderWithdrawalInput`…), `CheckoutResult` with `toPaymentDataPairs()`, `PaymentResultCode` and `AccountSubscriptionPaymentMethodResult`, the checkout types from `@cocartheadless/checkout` (`PlaceOrderInput`, `SavedPaymentMethod`, `CheckoutState`…) and the extension data for CoCart Plus's supported plugins (`CartExtensions`, `CartItemExtensions`, `ProductExtensions` and their shapes).
